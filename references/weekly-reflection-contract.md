# Weekly reflection contract

`weekly-reflection.json` 用于自然周汇总表。它把周一到周日的短线索压缩成可扫读的主题与结果，不复制七份日报，也不推断精确工时。

```json
{
  "headline": "围绕接口兼容与交付准备推进",
  "note": "这是一周的数字线索摘要，不是完整工时记录。",
  "themes": ["接口兼容", "交付准备"],
  "days": [
    {
      "date": "2025-03-10",
      "summary": "梳理接口兼容方案",
      "themes": ["接口契约"],
      "results": ["确认旧客户端的兼容处理方式"]
    }
  ]
}
```

## 编写规则

- 自然周范围固定为周一 00:00 至下周一 00:00，`days` 必须按日期包含周一到周日七项。
- `headline` 只概括整周事项和结果，不强调工作时长。
- `themes` 是整周的三至五个主要方向；没有足够证据时可以更少。
- 每天的 `summary` 是一句不超过 100 字的工作概括。
- 每天最多三个 `themes` 和三个 `results`，每项不超过 80 字；合并同类事项，避免逐条复述任务标题。
- 某天没有线索时写“暂无可见线索”，并使用空的 `themes` 与 `results`；不能推断为休息、摸鱼或没有工作。
- 只使用 `evidence.json` 中的短标题、结果首句以及用户本人补充。不要回读或复制原始 Codex 对话。
- 跨主机重复事件已经在 evidence 层合并，周摘要不要按 `host_ids` 重复计算工作内容。
